## Authoring record (GM-460/S7)

**Targets used.** Each corpus uses the first N non-skipped rows of its
seed-460 target list (`v2/new/targets/<corpus>.jsonl`), N = the stage-2
allocation: gin 30, py-requests 80, ripgrep 40, g-mesh 40, excalidraw 65,
task-tracker-mcp 15. `confirm/check_targets.py ... --seed 460 --against
eval/embedding --against eval/embedding/confirm` passes: no new target is a
consumed row or an expected symbol of either earlier study.

**Additional acceptable answers.** A File target and its Module node are the
same module, so each module query lists both (py-requests #30, #54, #66, #79,
#84; ripgrep #40 lists the `human` module and its only function).
Byte-identical twins in another plugin are listed too (g-mesh #5
`Positions::new`, #19 `Emitter::file_id`, #21 `Emitter::finish`, Rust and
Python plugins). Where a twin exists but the query names one side, the
derivation says so (g-mesh #24 and #40, Rust census vs Python census).
No added symbol is a GM-398 or confirm expected symbol.

**Absent queries.** Each derivation records the grep that proves absence and
its hit count; non-zero hits are named and shown to be unrelated (for
example `socks` was dropped for py-requests because SOCKS proxies are
supported through urllib3, and a dark-mode query for task-tracker-mcp because
its CSS follows `prefers-color-scheme`).
